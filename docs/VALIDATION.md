# 候选验收与回退

## 已授权的本地检查

构建、JVM/Robolectric 生命周期测试、Lint、APK 元数据/签名/原生库摘要检查、源码与分发包保密扫描。实际结果统一记录 BUILD-RESULTS.md。不得把这些检查称为 MIUI 实机验收。

## 安装前的单独确认

先审阅 APK 摘要、包名、签名、检查结果与限制，再确认安装独立候选、停止原应用的当前 EasyTier 会话及切换时间窗。安装独立候选不会修改原应用数据，但启动相同节点身份/IP 和回环端口前必须先停止原实例。不得同时争用节点或端口，不修改现有服务地址/FlClash VPN，也不导出原应用的整份私人配置。导入使用用户保管的本地受限配置；发布包只附虚构示例。

本开发任务没有执行上述安装与切换。使用者随后报告长时间保活及锁屏成功，具体版本和测试条件见 [DEVICE-FEEDBACK.md](DEVICE-FEEDBACK.md)；不据此推定下面每项场景均已验收。

## 真机矩阵（待执行）

| 场景 | 必须观察的结果 |
|---|---|
| 初次连接 | 普通前台 Service 存在；通知与核心 STARTING/RUNNING 一致；没有新 VPN 接管；回环 SOCKS 工作 |
| 通知拒绝/渠道禁用 | 启动明确失败，没有核心或“运行中”残留；恢复通知权限后能明确重连 |
| 接管/重复连接 | 同一会话与核心持续存在，无第二节点或重复监听 |
| 断开/通知停止 | 原生实例、SOCKS 监听、peer、前台服务和恢复意图一起结束；旧回调不能复活 |
| 核心启动失败/异常退出 | 错误与通知清理可见；不周期强停重启，不假报网络在线 |
| 后台/切换真实客户端 | 分时记录 PID、cgroup frozen、前台服务、远端 peer、匿名严格 TLS 200/401；验证两个真实客户端同步 |
| 熄屏 15/60 分钟 | 同时检查冻结与可达性；服务存在不代替实际流量测试 |
| 移动数据/Wi-Fi/重连 | 分别标记底层网络和时长；保持证书链、主机名验证开启；不保存正文或认证内容 |
| 低内存终止 | 记录系统确认为 LOW_MEMORY；若系统 sticky 重建，确认是新 PID、真实新核心、一次恢复与可达性；没有重建也如实失败 |
| 第二次系统终止 | 自动恢复预算耗尽，服务停止、界面不假报运行；明确 Connect 后才重置预算 |
| 用户 force-stop/活跃应用停止 | 不承诺自动恢复；重新打开后不能凭空认为已连接 |
| 设备重启 | 只在用户主动开启 Start on boot 后验证；解锁/厂商自启动限制单独记录 |

模拟调用 `onStartCommand(null)` 仅验证重建代码路径，不能冒充真实系统低内存终止；`am kill` 对前台服务可能不生效，force-stop 又改变恢复资格，二者都不能冒称 LOW_MEMORY。日志仅限相关包和短窗口，输出必要脱敏字段，不读取笔记/密码库内容。

## 回退

停止独立候选，确认其核心/端口已释放；再打开保留的原应用并用现有配置明确连接。FlClash、服务地址、服务器与原应用数据不变。是否卸载独立候选由用户决定；卸载只删除候选包的数据，不能清理原应用数据。若无法确认候选原生释放成功，先确认候选进程结束再启动原实例，不能并行争用身份与端口。
